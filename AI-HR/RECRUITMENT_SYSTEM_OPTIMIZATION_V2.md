# 企业级生产环境：高可用角色驱动面试架构方案 (V2)

## 0. 设计背景
招聘系统的核心价值在于“精准”与“效率”。现有的通用评估逻辑在面对跨行业、多职能岗位时，往往深度不足，且单机瓶颈无法支撑真实的生产级流量。本方案通过 **解耦核心业务、引入技能矩阵（Skills Matrix）权重、以及多层容错机制**，构建一套真正可落地的企业级 AI 招聘底座。

---

## 1. 核心架构：三层演进模型

### 1.1 基础设施层 (Infrastructure) - 高可用基石
- **异步任务编排**：弃用单线程轮询，全面接入 **Celery + RabbitMQ/Redis**。
    - 将简历同步、附件解析、AI 评估、报告生成定义为不同的异步任务流。
    - 针对大并发场景，支持动态增减 Worker 节点，实现弹性扩容。
- **多模型负载均衡 (Model Failover)**：
    - 建立 `AIModelRouter` 模块，配置首选模型（如 GPT-4）与备选模型（如 DeepSeek/Qwen）。
    - 接口层支持配置“并发配额（Quota）”，自动熔断超出水位线的请求，并无缝降级到备选方案。
- **分布式幂等性控制**：
    - 利用 Redis 分布式锁确保同一个候选人的同一份简历在被多处调用时，评估任务只会被触发一次，节省 Token 成本并保证数据一致性。

### 1.2 领域能力层 (Domain Logic) - 核心 Skills 引擎
- **能力矩阵中心 (Competency Matrix Hub)**：
    - **技能注册制**：建立标准的技能库（如：分布式一致性、成本核算、商务谈判等），每个技能映射具体的“考察参考点（Signals）”。
    - **角色画像化 (Role Persona)**：岗位不再仅仅是一个 `job_title`。后台为每个岗位配置一个 `SkillWeightMatrix`。
- **证据导向的 AI 评估**：
    - LLM 评估时，任务被细化为多个子 Prompt。
    - **不再只打“分”**：强制 LLM 输出“证据点”。(例：评估 Java 并发能力，必须在简历中找到“独立分析并修复线上死锁问题”的具体描述)。
    - 自动计算“技能分差 (Delta Score)”，识别候选人的核心短板。

### 1.3 实时交互层 (Adaptive Interview) - 闭环反馈
- **自适应追问策略**：
    - 评估阶段生成的“技能短板记录”会作为上下文（Context）实时传递给 AI 面试官。
    - 面试官在对话中会自动调整“探针（Probes）”，针对性地考察这些短板，补全评估证据链。
- **Human-in-the-Loop (HITL) 反馈回路**：
    - HR 可以在后台对 AI 的某项技能打分进行修正。
    - 系统自动将此类“负反馈”记录为 Few-shot 样本，通过持续监督学习动态调优评估 Prompt 的精准度。

---

## 2. 真实落地：技术路线图 (Roadmap)

### 第一阶段：标准化与结构化 (1-2周)
- 定义 `ai_hr/domain/persona` 下的 JSON 格式技能矩阵。
- 对齐 MySQL 数据库，在 `candidate_job_evaluations` 中扩展 JSON 类型的维度得分字段。

### 第二阶段：异步流水线建设 (2-3周)
- 集成 Celery 框架，实现“同步-解析-评估”的完全异步化。
- 建立 `TraceID` 追踪体系，实现从“候选人进入系统”到“面试报告产出”的全链路监控。

### 第三阶段：高可用加固 (1周)
- 实现 API 熔断器与多 LLM 提供商切换逻辑。
- 加入数据脱敏中间件 (Data Masking)，确保发送至外部 API 的文字母集不含 PII。

---

## 3. 安全与合规建议
- **数据合规**：建议在云环境部署 **本地化解析引擎（如 doc2text-local）**，敏感解析不经过公网。
- **审计留痕**：保留 AI 决策的每一个 `AI_Decision_Log`，包括当时的 Prompt 模板版本、模型原始返回以及最终解析结果。

---

## 4. 方案总结
本方案通过 **“画像驱动评估 -> 评估指导面试 -> 面试修正画像”** 的闭环设计，解决了传统招聘系统“评估流于表面”和“面试千篇一律”的痛点。
在生产环境下，凭借其 **异步弹性弹性** 与 **多模型容错** 的设计，能够确保系统在高负载下的逻辑确定性与服务持续性。
