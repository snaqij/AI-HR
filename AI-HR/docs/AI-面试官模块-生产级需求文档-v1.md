## 2. 背景与目标
当前 AI-HR 已具备岗位、候选人、会话、评分、面试排期等能力，但“AI 面试官实时语音面试”尚未形成端到端闭环。  
本需求目标是构建一个可生产上线的 AI 面试官模块，实现：

1. 候选人通过专属链接进入面试页，支持语音通话与可选视频。
2. AI 面试官在面试前基于简历自动生成问题清单（含追问策略）。
3. 面试中 AI 语音提问、实时听取候选人回答并动态追问。
4. 面试后自动输出结构化评估报告、评分与风险标签，回写 AI-HR。

---

## 3. 范围定义
### 3.1 In Scope（本期范围）
1. 面试会话创建、入会、断线重连、超时结束。
2. 实时音频链路：候选人音频 -> ASR -> LLM -> TTS -> 候选人播放。
3. 候选人视频上行（用于展示，不做本期视觉识别评分）。
4. 面试前“简历驱动问题集”生成（岗位要求 + 简历经历 + 风险标签）。
5. 面试中状态机（开场、核验、技术问题、项目追问、反问、收尾）。
6. 面试后报告（摘要、问题-回答、维度评分、风险项、建议结论）。
7. 与现有 AI-HR 数据与流程联动（candidates/interviews/score/events）。

### 3.2 Out of Scope（本期不做）
1. 情绪/表情视觉模型评分（视频分析）。
2. 跨语言同传面试（多语种同时支持）。
3. 薪资谈判自动化决策。
4. 候选人身份核验的人脸比对。

---

## 4. 业务角色与使用场景
### 4.1 业务角色
1. 招聘运营（HR）：发起 AI 面试、查看报告、人工复核。
2. 候选人：通过邀请链接参与面试。
3. 面试官管理者：配置题库策略、阈值、模板与禁问规则。
4. 系统管理员：监控质量、成本、合规与回滚。

### 4.2 核心场景
1. 候选人已投递，系统自动触发 AI 初面。
2. HR 手动发起 AI 面试并选择时间窗口。
3. 面试异常中断后，候选人重连继续。
4. 低置信度或敏感内容命中时，系统转人工接管。

---

## 5. 端到端业务流程
1. 面试计划创建：HR 选择岗位、候选人、时段，系统生成面试链接。
2. 面试前准备：
   - 拉取候选人简历结构化画像（已有模块）
   - 拉取岗位 JD 与评分维度
   - 生成“问题清单 + 追问树 + 禁问过滤”
3. 候选人入会：设备检测（麦克风/扬声器/网络），成功后进入等待区。
4. 面试执行：
   - AI 开场说明与录音告知
   - 按问题流提问，实时转写候选人回答
   - LLM 进行回答理解、追问决策、节奏控制
   - 异常时触发兜底（重复提问/文字提示/转人工）
5. 面试结束：
   - 生成结构化报告
   - 回写 candidate score / risk tags / interview status
   - 产生日志与审计事件

## 6. 功能需求（FR）
### FR-01 面试前问题生成
1. 输入：`candidate_id`、`job_id`、简历画像、岗位要求、历史标签。
2. 输出：问题集（必问、可选追问、禁止问题过滤后结果）。
3. 要求：
   - 每题包含：问题目标、评分维度、期望回答信号、追问条件。
   - 题量可配置（默认 8~12 题）。
   - 支持按岗位类型模板化。

### FR-02 实时语音面试
1. AI 语音播报问题（TTS）。
2. 候选人语音回答实时转写（ASR）。
3. 支持静音、重说、网络抖动下恢复。
4. 面试时长可配置（默认 20~35 分钟）。

### FR-03 视频能力（可选）
1. 候选人可开启视频上传。
2. 本期仅用于面试体验与回放，不参与自动评分。

### FR-04 面试状态机与流程控制
1. 状态：`created -> waiting -> in_progress -> completed/failed/interrupted -> reviewed`
2. 阶段：`intro -> verification -> core_questions -> deep_dive -> candidate_questions -> closing`
3. 超时、无响应、ASR 连续失败时进入兜底分支。

### FR-05 自动评估与报告
1. 输出面试报告：
   - 总结摘要
   - 逐题问答与关键证据片段
   - 维度分（技术/沟通/项目匹配/稳定性）
   - 风险标签（夸大经历、答非所问、信息不足等）
   - 结论建议（推进/待复核/不推进）
2. 回写到现有评分体系，支持与 AI scoring 融合。

### FR-06 人工接管与回滚
1. 低置信度连续触发时自动转人工。
2. 敏感内容触发时立即停止自动提问并记录事件。
3. 支持一键切换“规则模式”（关闭 LLM 生成，仅执行模板问题）。

### FR-07 运营与管理
1. 模板管理：岗位问题模板、禁问词、追问规则。
2. 运行时开关：模型、阈值、灰度、回滚。
3. 质量看板：接通率、完成率、平均时长、转人工率、满意度。

## 7. 非功能需求（NFR）
### 7.1 性能
1. 端到端语音交互延迟（候选人停顿到 AI 发声）P95 <= 1800ms。
2. ASR 片段转写延迟 P95 <= 700ms。
3. 单场面试稳定运行 >= 45 分钟。

### 7.2 可用性
1. 面试服务可用性 >= 99.9%。
2. 会话断线自动重连成功率 >= 98%。

### 7.3 稳定性
1. 关键链路可降级（TTS/LLM/ASR 任一故障时可回退文本问答/转人工）。
2. 全链路幂等（重放消息、重复回调不造成重复状态写入）。

### 7.4 安全与合规
1. 面试前明确告知录音/转写并获得同意。
2. PII 脱敏存储与访问控制（最小权限）。
3. 敏感问题拦截（歧视、隐私、违规话题）。
4. 审计日志全留痕，支持追溯。

## 8. 技术方案（生产级）
### 8.1 架构分层
1. `Interview Orchestrator`：业务编排、状态机、回写 AI-HR。
2. `RTC Gateway`：会议会话、音视频流管理、重连控制。
3. `Speech Layer`：ASR/TTS 统一适配与降级。
4. `LLM Runtime`：问题生成、追问决策、回答评估。
5. `Policy Guardrails`：敏感拦截、低置信度转人工、节奏限制。
6. `Observability`：trace、指标、告警、审计。

### 8.2 核心策略
1. 先生成“结构化问题树”，面试中再动态挑选，避免纯自由生成失控。
2. 每轮问答输出 `confidence + policy_flags + reason`。
3. 连续 N 次低置信度（默认 2）触发 handoff。
4. 敏感命中直接 blocked，不继续提问。

## 9. 数据模型（草案）
1. `ai_interview_sessions`
   - `id, candidate_id, job_id, status, started_at, ended_at, channel, rtc_room_id, created_at`
2. `ai_interview_question_sets`
   - `id, session_id, version, questions_json, source(resume+jd), created_at`
3. `ai_interview_turns`
   - `id, session_id, turn_no, speaker(ai/candidate), transcript, audio_uri, confidence, latency_ms, policy_flags, created_at`
4. `ai_interview_reports`
   - `id, session_id, summary, dimension_scores_json, risk_tags_json, recommendation, created_at`
5. `ai_interview_handoffs`
   - `id, session_id, reason, trigger_flags, operator, created_at`

## 10. 接口需求（草案）
1. `POST /api/v1/ai/interviews/sessions`
   - 创建面试会话并返回候选人入会链接。
2. `POST /api/v1/ai/interviews/sessions/{id}/question-set/generate`
   - 基于简历/JD 生成问题集。
3. `POST /api/v1/ai/interviews/sessions/{id}/start`
   - 启动面试状态机。
4. `POST /api/v1/ai/interviews/sessions/{id}/events`
   - 上报实时事件（ASR 片段、设备状态、网络状态）。
5. `POST /api/v1/ai/interviews/sessions/{id}/handoff`
   - 人工接管。
6. `POST /api/v1/ai/interviews/sessions/{id}/finish`
   - 结束并触发报告生成。
7. `GET /api/v1/ai/interviews/sessions/{id}/report`
   - 获取面试报告。

## 11. 关键验收指标（KPI/SLA）
1. 面试接通率 >= 95%。
2. 面试完成率 >= 85%。
3. 自动报告可用率 >= 98%。
4. 低置信度转人工召回率 >= 95%。
5. 敏感问题漏拦截率 <= 1%。
6. 面试官人工复核一致率（AI 建议 vs 人工结论）>= 80%。

---

## 12. 风险与对策
1. 音频链路延迟高：
   - 对策：分段转写、短句播报、本地缓冲与并发优化。
2. 模型幻觉/失控追问：
   - 对策：问题树约束 + policy guardrail + hard stop 机制。
3. 合规风险：
   - 对策：录音同意、禁问词库、人工复核与审计。
4. 候选人体验不佳：
   - 对策：清晰引导、失败重试、随时转人工入口。

## 13. 里程碑计划（建议）
1. M1（2 周）：需求冻结 + 架构评审 + 数据模型与接口定稿。
2. M2（3 周）：RTC/ASR/TTS/状态机 MVP（可跑通单场面试）。
3. M3（2 周）：简历问题生成 + 报告回写 + 风险策略。
4. M4（2 周）：压测、灰度、合规审计、线上观测与回滚演练。

---

## 14. 与当前 AI-HR 的集成关系
1. 复用简历能力：`/api/v1/ai/resume/*` 输出作为问题生成输入。
2. 复用评分能力：`/api/v1/ai/candidates/score` 融合面试报告分。
3. 复用运行时治理：feature flag / model config / prompt version。
4. 复用治理能力：approvals、audit、funnel 进入统一看板。

---

## 15. 上线策略
1. 灰度顺序：内部测试岗位 -> 单部门 -> 全量岗位。
2. 版本策略：`rule_only` / `llm_assist` / `llm_full` 三档可回滚。
3. 失败策略：实时链路异常时自动切文本问答或转人工。
4. 回滚标准：延迟超阈、投诉率异常、敏感拦截异常立即回滚。
