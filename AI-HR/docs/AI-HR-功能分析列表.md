# AI-HR 功能分析列表

## 1. 文档说明
- 文档目的：定义 AI-HR 产品的功能边界、模块清单、优先级和验收口径，用于产品、研发和运营协同落地。
- 适用阶段：0-1 搭建期到小规模上线期。
- 版本：v1.0（MVP 导向）。

## 2. 产品定位
AI-HR 是一个招聘自动化与智能决策平台，核心目标是提升招聘效率与质量，覆盖从职位发布到面试安排的关键链路。平台采用 `API-first + Agent 编排` 思路，优先通过标准接口调用业务能力，网页自动化仅作为补充兜底。

## 3. 目标用户与角色
- 招聘负责人：关注招聘效率、漏斗转化率、招聘成本。
- 招聘专员（HR）：关注职位发布、简历处理、候选人沟通、约面效率。
- 面试官：关注候选人质量、面试安排效率、评估一致性。
- 业务用人经理：关注招聘进度、候选人匹配度、决策可解释性。
- 系统管理员：关注权限、审计、安全与合规。

## 4. 功能架构总览
- 渠道连接层：BOSS、智联、猎聘、拉勾等渠道连接器。
- 招聘业务层：职位、候选人、流程状态、面试安排。
- AI 能力层：简历解析、匹配评分、话术生成、时间协商。
- Agent 编排层：任务规划、工具调用、策略执行、异常恢复。
- 治理与安全层：权限、审批、审计、合规规则。

## 6. 与 BOSS 接入的专项能力清单

### 6.1 目标能力
- 自动发布职位。
- 自动打招呼。
- 自动接收简历。
- 自动回复消息。
- 自动约面试时间。

### 6.2 接入设计建议
- 连接器抽象：统一定义 `publish_job`、`list_applicants`、`send_message`、`schedule_interview` 等标准动作。
- 任务编排：通过 Agent 决策调用连接器动作，不直接耦合渠道页面结构。
- 状态回写：将每次渠道动作回写到 ATS 主档案，保证单一事实源。
- 兜底机制：API 不可用场景可配置人工处理或网页自动化补充。

### 6.3 风险与边界
- 渠道规则风险：不同平台对自动化操作有协议限制，需先完成合规评估。
- 稳定性风险：网页自动化易受页面改版影响，应限制在兜底场景。
- 账号安全风险：需提供账号托管、安全审计与操作留痕。

## 7. 端到端核心流程
1. 创建岗位并审核 JD。
2. 发布到目标渠道并回收发布状态。
3. 接收简历并完成解析、去重与评分。
4. 对入围候选人自动触达并进行意向沟通。
5. 达成意向后自动约面并发送会议邀请。
6. 面试后回收反馈，推进下一阶段或结束流程。

## 8. MVP 范围（建议）
- 包含：岗位发布、简历接收解析、自动打招呼、自动回复、自动约面、流程看板、审计日志。
- 不含：全自动 Offer 发放、完全无人值守决策、复杂薪酬谈判代理。

## 9. 验收标准（示例）
- 发布成功率：目标 >= 95%。
- 简历解析成功率：目标 >= 92%。
- 自动回复准确率：目标 >= 85%（人工抽检口径）。
- 约面成功率：目标 >= 70%（目标人群范围内）。
- 全链路可追溯率：100%（关键动作均有审计日志）。

## 10. 非功能要求
- 安全：传输加密、敏感字段脱敏、细粒度权限。
- 稳定性：关键任务支持重试、幂等和补偿。
- 可观测：日志、指标、告警、链路追踪完整。
- 可扩展：新增渠道接入成本可控，尽量无需改动核心流程。

## 11. 实施建议
- 先做半自动：AI 建议 + 人工确认，降低早期风险。
- 先做单渠道试点：先打通一个渠道，再复用连接器扩展多渠道。
- 先立统一数据模型：候选人、职位、会话、面试对象必须标准化。
- 先上治理能力：审批、审计、权限与合规应与业务能力同步建设。
