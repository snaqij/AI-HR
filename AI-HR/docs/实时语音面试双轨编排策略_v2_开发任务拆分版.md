# 实时语音面试双轨编排策略 v2 - 开发任务拆分版

## 文档目标

把当前“预生成题目未严格执行、公司信息回答不稳定”的问题，落成一套可以直接开工的工程任务。

本版策略的核心约束只有两条：

- 面试主流程严格按预生成 `question_pack` 和既定阶段推进
- 公司信息只能在尾段基于给定 `company_info` 回答，不能让 LLM 自由发挥

---

## 总体原则

- `ai_hr` 负责准备唯一可信输入
  - `question_pack`
  - `company_info`
- `ten_agent` 负责实时执行
  - 按题库播报主问题
  - 按状态机推进阶段
  - 仅在允许范围内调用 LLM
- LLM 权限收口
  - 不负责主问题生成
  - 不负责阶段推进
  - 不负责中途公司信息回答
  - 只负责技术追问

## Task 1

### 统一运行时输入源

### 目标

- 让 `ten_agent` 启动时优先拿到 `ai_hr` 注入的 `question_pack`
- 让 `company_info` 通过统一链路注入到 TEN property
- 让运行时日志可以明确追踪题包和公司信息来源

### 涉及文件

- `AI-HR/ai_hr/services/ai_interviews.py`
- `AI-HR/ai_hr/services/ten_runtime.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`
- `AI-HR/ai_hr/services/interview_runtime/question_schema.py`

### 改动内容

#### 1. `ai_interviews.py`

- 在 session 创建 / 启动 / prepare TEN 之前，确保 runtime payload 含有完整 `question_pack`
- 补齐以下字段：
  - `question_pack`
  - `question_pack_source`
  - `question_pack_version`
- 保持以下字段继续由统一装配函数产出：
  - `company_info`
  - `company_info_source`
  - `company_info_version`

#### 2. `ten_runtime.py`

- 在 `interview_orchestrator` 节点 property 中正式注入：
  - `question_pack`
  - `question_pack_source`
  - `question_pack_version`
  - `company_info`
  - `company_info_source`
  - `company_info_version`

#### 3. `main.py`

- `on_init()` 调整题包加载优先级：
  1. TEN property 注入的 `question_pack`
  2. 本地 `data/interview_questions.json`
  3. `build_stage_seed_questions(...)`
- `on_init()` 校验 `company_info` 是否存在
- 增加初始化日志：
  - `question_pack_loaded_from`
  - `question_pack_count`
  - `company_info_loaded`
  - `company_info_source`

#### 4. `question_schema.py`

- 增强 `normalize_question_pack()` 容错
- 保证最少补齐以下字段：
  - `question_id`
  - `stage`
  - `question`
  - `question_type`
  - `topic_name`
  - `topic_aliases`

### 输入输出变化

#### 输入新增

- `question_pack`
- `question_pack_source`
- `question_pack_version`

#### 输出增强

- TEN property 内含完整题包和公司资料
- 初始化日志可追踪当前运行时来源

### 验收标准

- TEN 启动日志明确显示题包来源为 `ai_hr_runtime`
- 实时面试主问题顺序与 `question_set_preview.json` 一致
- `company_info` 启动时可确认已装载
- 即使本地题库文件存在，也不会覆盖已注入题包

### 风险点

- `question_pack` 过大导致 property 文件膨胀
- 历史 session 未预生成题包时仍需 fallback
- 不同来源题包结构不统一导致归一化失败

## Task 2

### 统一阶段推进与题目切换决策

### 目标

- 让“当前该问哪题、是否追问、是否切题、是否切阶段”由共享 runtime 决策层统一输出
- 避免 `main.py` 再做本地二次判定，导致流程漂移

### 涉及文件

- `AI-HR/ai_hr/services/interview_runtime/runtime_engine.py`
- `AI-HR/ai_hr/services/interview_runtime/question_flow.py`
- `AI-HR/ai_hr/services/interview_runtime/flow_policy.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

### 改动内容

#### 1. `runtime_engine.py`

- 扩展 `RuntimeTurnDecision`
- 新增建议字段：
  - `output_mode`
  - `target_question`
  - `must_transition`
  - `transition_brief`
  - `followup_budget_remaining`
  - `defer_company_qa`

#### 2. `question_flow.py`

- 扩展 state：
  - `current_question_id`
  - `current_question_status`
  - `current_question_asked`
  - `current_output_mode`
  - `state_version`
- 固定题目状态：
  - `pending`
  - `scripted_asked`
  - `followup_active`
  - `completed`

#### 3. `flow_policy.py`

- 明确阶段边界：
  - `S1` 仅做开场与连通性确认
  - `S2` 仅做自我介绍与画像锚定，不长时间深挖
  - `S3-S6` 进入正式技术题逐题推进
  - `S7` 为尾段公司介绍与候选人反问
  - `S8` 为固定收尾

#### 4. `main.py`

- 保留特殊阶段分支：
  - `OPENING`
  - `COMPANY_QA`
  - `CLOSING`
- 一般技术流程不再自己判定切题，统一消费 runtime decision

### 输入输出变化

#### 输入

- 当前 state
- `question_pack`
- 候选人 transcript

#### 输出

- 统一 `RuntimeTurnDecision`
- `main.py` 按决策执行，不再重复推理

### 验收标准

- `S2` 不会一直停留在自我介绍深挖
- `S3-S6` 能按题库逐题推进
- 达到追问上限或证据充分后，稳定切下一题
- 阶段推进能通过日志清晰观察

### 风险点

- 现有 `derive_stage()` 和新状态字段兼容性
- `StageProgressEngine` 与新 flow 的边界需要重新对齐
- 老逻辑中的 `transition_reason` 需要兼容迁移

## Task 3

### 落地双轨执行：主问题直出，LLM 只追问，公司问题中途只延后

### 目标

- `S3-S6` 主问题直接播题库原题
- LLM 只负责短追问
- `S1-S6` 中途公司类问题不展开回答，只做固定延后提示
- 只有进入 `S7` 时，才基于 `company_info` 做公司介绍

### 涉及文件

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/prompt_builder.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/session_context.py`
- `AI-HR/ai_hr/services/llm/prompts.py`

### 改动内容

#### 1. `main.py`

- 将 `_handle_interaction()` 收敛为：
  - `preprocess`
  - `special guard`
  - `runtime decision`
  - `scripted question / llm followup`
  - `tts emit`
- 新增辅助函数：
  - `_emit_scripted_question(...)`
  - `_run_llm_followup(...)`
  - `_normalize_candidate_transcript(...)`
  - `_is_company_question(...)`
  - `_emit_company_qa_defer_reply(...)`

#### 2. 中途公司问题处理规则

- 当候选人在 `S1-S6` 中问公司问题时：
  - 不切到 `S7`
  - 不调用自由 LLM 回答
  - 不记录待回答问题
  - 固定回复：
    - “这些我会在面试最后统一介绍，我们先继续当前面试流程。”
- 回复后立即回到当前面试主线

#### 3. `prompt_builder.py`

- `PromptBuildInput` 增加：
  - `output_mode`
  - `target_question_id`
  - `followup_budget_remaining`
- 只在 `llm_followup` 模式下组装 follow-up prompt

#### 4. `prompts.py`

- follow-up prompt 加强约束：
  - 不重述主问题
  - 不改写题库原题
  - 只允许一条短追问
- company QA prompt 加强约束：
  - 只能依据 `company_info`
  - 不得编造公司名称、业务、团队、岗位、福利
  - 资料缺失时要明确说明

#### 5. `session_context.py`

- 增加字段：
  - `current_scripted_question_id`
  - `current_scripted_question_text`
  - `last_followup_text`
- 让 scripted question 和 follow-up 都能进入稳定上下文

### 输入输出变化

#### 输入新增

- `output_mode`
- `followup_budget_remaining`
- `normalized_transcript`

#### 输出变化

- 主问题由题库直接进入 TTS
- 追问才调用 LLM
- 中途公司问题只返回固定延后话术

### 验收标准

- `S3-S6` 首问不等待 LLM
- 每题首问与题库原题一致
- 中途问“你们公司做什么”时，不会自由回答
- 到 `S7` 时，公司介绍内容稳定且一致
- 不再出现资料外虚构答案

### 风险点

- scripted question 与 `question.update/question.final` 时序对齐
- `current_question_buffer` 可能与 scripted emit 发生冲突
- 延后回复后必须保证主线状态不被污染

## 一句话总结

本次改造的重点不是继续调 prompt，而是收紧控制权：

- 题目由 `question_pack` 决定
- 流程由 shared runtime 决定
- `ten_agent` 只执行
- LLM 只追问
- 公司信息只在尾段按给定资料回答
