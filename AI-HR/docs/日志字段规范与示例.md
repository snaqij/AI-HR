# 日志字段规范与示例

## 目标
- 统一业务日志结构，支持跨模块排障与链路追踪。
- 在关键链路中最少包含：`trace_id`、`session_id`、`candidate_id`、`job_id`（按场景可为空字符串）。

## 字段定义
- `trace_id`：一次业务链路的跟踪标识。  
  建议：
  - 调度任务链路：使用运行实例 ID（如 `agent_run.id`）。
  - 会话链路：可使用 `session_id` 作为 `trace_id`。
- `session_id`：AI 面试会话 ID（无会话场景填空或不打）。
- `candidate_id`：候选人 ID。
- `job_id`：岗位 ID。
- `event`：推荐放在消息前缀（如 `ai_resume.auto_request.request_success`）。

## 日志级别建议
- `DEBUG`：高频调试信息（包长、分片、细粒度状态）。
- `INFO`：关键状态流转（开始、完成、命中分支）。
- `WARNING`：可恢复异常、降级、重试。
- `ERROR/EXCEPTION`：不可恢复错误；`logger.exception` 自动带堆栈。

## 示例
```python
logger.info(
    "ai_resume.auto_request.request_success trace_id=%s candidate_id=%s job_id=%s request_status=%s",
    trace_id,
    candidate_id,
    job_id,
    request_status,
)
```

```python
logger.exception(
    "recruitment_automation.evaluate.failed trace_id=%s candidate_id=%s job_id=%s",
    trace_id,
    candidate_id,
    job_id,
)
```

```python
logger.debug(
    "ai_interview.ws.duplex_open trace_id=%s session_id=%s",
    session_id,
    session_id,
)
```

## 禁止项
- 业务目录禁止使用 `print(...)` 输出日志。
- 禁止在日志中输出密钥、token、明文凭据等敏感信息。
