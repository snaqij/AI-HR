# 实时语音面试双轨编排策略 v1 - 按文件实施清单版

## 文档目标

从“按任务”视角切换到“按文件”视角，明确每个文件应该改什么、为什么改、改完要达到什么状态。

---

## 1. `AI-HR/ai_hr/services/interview_runtime/runtime_engine.py`

**职责定位**

- 共享运行时裁决中心

**要改什么**

- 扩展 `RuntimeTurnDecision`
- 新增：
  - `output_mode`
  - `target_question`
  - `prefetch_question`
  - `should_prefetch_next`
  - `transition_brief`

**改完后应达到**

- 能明确告诉执行器：
  - 这一轮是 scripted 还是 llm
  - 当前应该播哪一道题
  - 是否应该准备下一题

**注意点**

- 不要在这里写 TTS 行为
- 只做纯决策，不做副作用

---

## 2. `AI-HR/ai_hr/services/interview_runtime/question_flow.py`

**职责定位**

- 题目状态推进与阶段同步

**要改什么**

- state 新增：
  - `current_question_asked`
  - `current_question_id`
  - `current_question_status`
  - `current_output_mode`
  - `state_version`
- 增加主问题已播、追问进行中、题目完成的显式流转

**改完后应达到**

- 主问题直出后，状态机知道这题已经播过
- 追问不会误推进 `active_question_index`
- 只有真正完成题目时才切下一题

**注意点**

- 与 `derive_stage()` 保持兼容
- 与 `StageProgressEngine` 保持配合

---

## 3. `AI-HR/ai_hr/services/interview_runtime/flow_policy.py`

**职责定位**

- 阶段策略定义

**要改什么**

- 重点复核 S2 的边界
- 必要时补充：
  - 是否允许主问题直出
  - 是否允许多轮追问
  - 是否允许深挖

**改完后应达到**

- S2 明确是画像锚定阶段
- S3-S6 明确进入正式 scripted question 阶段

**注意点**

- 不要在 policy 里混入执行逻辑

---

## 4. `AI-HR/ai_hr/services/llm/prompts.py`

**职责定位**

- LLM 跟随式追问约束

**要改什么**

- `build_interview_stage_instruction()` 增强 follow-up only 约束
- 明确：
  - 不复述主问题
  - 不改写题库原题
  - 只允许一条短追问
  - 必须切题时只做一句短收束

**改完后应达到**

- LLM 输出明显偏“追问”
- 不再替代 scripted question

**注意点**

- 这层只管约束，不管题序

---

## 5. `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

**职责定位**

- 实时语音执行器主链路

**要改什么**

- `_handle_interaction()` 拆成双轨分支
- 新增：
  - `_emit_scripted_question(...)`
  - `_run_llm_followup(...)`
  - `_maybe_prefetch_next_question(...)`
  - `_normalize_candidate_transcript(...)`

**改完后应达到**

- S3-S6 主问题可直接播放
- 追问才走 LLM
- 达到上限时直接播下一题
- 当前题追问时后台可准备下一题

**注意点**

- 不能破坏：
  - 握手
  - 公司介绍
  - 收尾
  - arbiter
  - 中断逻辑

---

## 6. `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/session_context.py`

**职责定位**

- 本地稳定对话上下文

**要改什么**

- 新增：
  - `current_scripted_question_id`
  - `current_scripted_question_text`
  - `last_followup_text`
  - `prefetched_question_id`
  - `prefetched_question_text`
  - `prefetch_state_version`

**改完后应达到**

- scripted question 和 llm followup 都能被清楚记录
- prompt 历史不会混淆主问题和追问

**注意点**

- 保持现有 recent_turns 去重逻辑

---

## 7. `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/prompt_builder.py`

**职责定位**

- 追问 prompt 组装器

**要改什么**

- 把 prompt 使用场景收紧为 `llm_followup`
- 新增输入：
  - `output_mode`
  - `target_question_id`
  - `followup_budget_remaining`

**改完后应达到**

- prompt 不再承担主问题生成
- prompt 内容更聚焦

**注意点**

- scripted question 不应再进入这里

---

## 8. `AI-HR/ai_hr/services/interview_runtime/question_schema.py`

**职责定位**

- question pack 规范化

**要改什么**

- 确保每题补齐：
  - `question_id`
  - `question_type`
  - `topic_name`
  - `topic_aliases`
  - `focus_slot`
  - `focus_hint`

**改完后应达到**

- scripted question、runtime decision、prefetch、event payload 使用统一结构

**注意点**

- 保持旧 question pack 的兼容归一化

---

## 9. `AI-HR/ai_hr/services/ai_interviews.py`

**职责定位**

- question pack 生成入口

**要改什么**

- 当前阶段主要不做双轨执行改造
- 重点是保证 question item 的结构字段补齐
- 后续可补 `generation_mode` 到 response schema

**改完后应达到**

- 生成出来的题目适合 scripted 直接播报
- LLM 题和规则题结构统一

**注意点**

- 不要把实时执行逻辑重新塞回 ai_hr

## 一句话总结

按文件实施时，最关键的是先收口 `runtime_engine.py + question_flow.py + main.py` 这三处。

只要这三处改对，双轨编排主干就成立了；其它文件都是围绕这条主干补稳定性、体验和可观测性。
