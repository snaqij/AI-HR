# 候选人详情页企业级改造实施方案 v1

## 1. 文档目标
- 当前仓库未包含前端实现代码，本方案用于指导前端仓库改造候选人详情页。
- 目标是将页面从“信息堆叠”改为“决策导向”，满足企业级招聘场景的可读性与可执行性。

## 2. 设计目标（验收导向）
- 3 秒内识别：候选人价值、当前阶段、是否建议推进。
- 10 秒内完成：推进流程、发起沟通、安排面试之一。
- 全页样式克制统一：色彩、间距、控件语义一致，不出现风格拼贴。

## 3. 信息架构改造
采用 `顶部决策区 + 主内容区 + 侧边行动区` 三段式布局。

### 3.1 顶部决策区（固定）
- 必含字段：姓名、当前流程阶段、岗位、匹配总分、更新时间。
- 必含结论：`强项`、`风险`、`建议动作` 三个摘要标签。
- 按钮规则：仅保留 1 个主按钮（例如“推进到面试”），其余均为次级按钮。

### 3.2 主内容区（建议 8 栅格）
模块顺序固定如下：
1. 候选人摘要（3-5 行）
2. 匹配分析（总分 + 维度分）
3. 工作经历（时间线）
4. 教育与证书
5. 技能与项目
6. 面试与评语记录

要求：
- 长文本默认折叠，避免首屏过长。
- 每个模块首行展示结论，详细内容可展开。

### 3.3 侧边行动区（建议 4 栅格）
- 流程操作卡：推进、淘汰、转人才库。
- 沟通操作卡：发消息、发邮件、生成邀约。
- 任务提醒卡：待跟进、待反馈、风险提示。

要求：
- 侧边仅放“可执行动作”与“待处理事项”，不重复展示履历明细。

## 4. 视觉与样式规范
## 4.1 色彩语义
- 主色：1 个品牌主色。
- 语义色：`success`、`warning`、`danger`、`neutral`。
- 禁止：大面积渐变背景、同屏多高饱和强调色。

## 4.2 字体与层级
- 页面标题：24/600
- 模块标题：16/600
- 正文：14/400
- 辅助文本：12/400
- 说明文本对比度不低于 WCAG AA（建议 >= 4.5:1）

## 4.3 间距与容器
- 8pt 体系：8 / 12 / 16 / 24 / 32
- 页面最大宽度：1200-1360
- 卡片内边距：16 或 24（二选一，全页统一）
- 卡片间距：16
- 圆角统一：8

## 4.4 组件一致性
- Button：每个区块仅一个主按钮。
- Tag：仅使用低饱和背景，颜色与语义一一映射。
- Table：时间格式统一 `YYYY-MM-DD HH:mm`，空值统一 `--`。
- Score：维度展示最多 5 项，超过折叠。

## 5. 页面状态规范（企业级体验关键）
至少定义以下状态并保持样式一致：
- Loading：骨架屏，不使用抖动强动画。
- Empty：明确原因 + 推荐下一步动作。
- Error：可重试 + 错误编号（便于排障）。
- Partial：部分模块加载失败时，其它模块可继续可用。

## 6. 前端实现建议（Vue 3）
建议拆分为以下组件：
- `CandidateDetailHeader.vue`
- `CandidateDecisionSummary.vue`
- `CandidateScoreCard.vue`
- `CandidateExperienceTimeline.vue`
- `CandidateActionPanel.vue`
- `CandidateActivityFeed.vue`

建议建立统一样式 token（示例）：

```css
:root {
  --color-brand: #1768e5;
  --color-success: #1b8a4b;
  --color-warning: #b7791f;
  --color-danger: #c53030;
  --color-neutral: #4a5568;

  --text-title: 24px;
  --text-section: 16px;
  --text-body: 14px;
  --text-meta: 12px;

  --space-1: 8px;
  --space-2: 12px;
  --space-3: 16px;
  --space-4: 24px;
  --space-5: 32px;

  --radius-card: 8px;
  --container-max: 1280px;
}
```

## 7. 两周实施计划
### 第 1 周
1. 重构页面信息架构（不改业务逻辑）。
2. 接入统一 token（颜色/字号/间距/圆角）。
3. 统一按钮、标签、卡片、评分组件样式。

### 第 2 周
1. 完成加载态、空态、错误态、部分失败态。
2. 走查候选人全流程动作（推进、沟通、约面）。
3. 进行 HR 可用性评审并收敛样式细节。

## 8. 验收清单（发布前）
- 是否 3 秒内可读到候选人结论与流程阶段？
- 是否 10 秒内可完成一个推进动作？
- 是否全页只存在一个主视觉强调点？
- 是否所有模块间距和标题层级一致？
- 是否定义并验证四类状态（Loading/Empty/Error/Partial）？

## 9. 风险与依赖
- 风险：当前后端字段命名偏技术向，前端展示可能出现术语不统一。
- 建议：新增一层前端展示模型（ViewModel），统一业务术语与格式化逻辑。
- 依赖：前端仓库需提供候选人详情页实现入口与组件目录规范。
