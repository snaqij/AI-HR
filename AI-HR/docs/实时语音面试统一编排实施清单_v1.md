# 实时语音面试统一编排实施清单 v1

## 背景

当前系统存在两套并行但未完全对齐的面试编排逻辑：

- `ai_hr/services/ai_interviews.py` 内已经具备较完整的题库生成、题目规范化、运行时状态推进能力
- `ten_agent/ten_packages/extension/interview_orchestrator_python/main.py` 内又维护了一套本地 question pack、阶段推进与 prompt 编排逻辑

这导致以下问题：

- 后端主逻辑和实时执行链路行为不一致
- 自我介绍阶段容易无限追问
- 题库覆盖面无法稳定生效
- `ten_agent` 越来越像“第二个面试大脑”，维护成本高

本实施清单的目标是：

- 将面试编排主逻辑统一收敛到 `ai_hr`
- 让 `ten_agent` 只承担实时执行职责
- 实现“题库驱动、状态机推进、有限追问、可控转场、ASR 容错”的统一实时面试链路

---

## 总体原则

### 主逻辑归属

`ai_hr` 负责：

- 题库生成
- 题目规范化
- 阶段定义
- 追问上限
- 题目完成判定
- 阶段推进
- 候选人画像状态
- 主题状态
- ASR 语义归一

`ten_agent` 负责：

- RTC / VAD / ASR / TTS
- turn 切分
- 中断控制
- 流式输出
- 调用统一编排引擎并执行结果

### 总体改造顺序

1. 先建立统一编排内核
2. 再统一题库结构和状态字段
3. 再让 `ten_agent` 改为消费共享编排结果
4. 最后加入 ASR 容错和主题控制

---

## 第一个提交：先把共享编排骨架立起来

### 目标

在 `ai_hr/services/interview_runtime/` 下建立统一 runtime 编排入口，让后续 `ai_interviews.py` 和 `ten_agent` 都能共用它。

### 修改文件

- `AI-HR/ai_hr/services/interview_runtime/question_flow.py`
- `AI-HR/ai_hr/services/interview_runtime/stage_progress.py`
- `AI-HR/ai_hr/services/interview_runtime/flow_policy.py`
- 新增 `AI-HR/ai_hr/services/interview_runtime/runtime_engine.py`

### 需要修改的函数

#### 1. `InterviewQuestionFlowEngine.init_state`

文件：
`AI-HR/ai_hr/services/interview_runtime/question_flow.py`

修改内容：

- 初始化统一运行时字段
- 先只增不删，保证兼容

新增字段建议：

- `stage_turn_count`
- `question_completion_reason`
- `focus_experience`
- `focus_module`
- `active_question_type`
- `active_topic_name`
- `active_topic_rounds`
- `candidate_requested_move_on`
- `profile_collected`

#### 2. `InterviewQuestionFlowEngine.apply_turn_result`

文件：
`AI-HR/ai_hr/services/interview_runtime/question_flow.py`

修改内容：

- 去掉 `S1/S2/S3` 的 early return 特判
- 所有阶段统一进入题目完成逻辑
- 支持更多题目完成原因

建议新增入参：

- `stage_progress_completed: bool = False`
- `candidate_requested_move_on: bool = False`
- `stage_turn_limit_reached: bool = False`
- `topic_round_limit_reached: bool = False`

需要支持的完成原因：

- `question_completed`
- `followup_limit_reached`
- `topic_exhausted`
- `candidate_requested_move_on`
- `stage_turn_limit_reached`
- `insufficient_signal_but_force_advance`

#### 3. `StageProgressEngine.update`

文件：
`AI-HR/ai_hr/services/interview_runtime/stage_progress.py`

修改内容：

- 输出更适合编排层使用的结果
- `reason` 改得更明确，方便主流程判断是否推进

#### 4. `StageProgressEngine._snapshot_s2`

文件：
`AI-HR/ai_hr/services/interview_runtime/stage_progress.py`

修改内容：

- 降低 `S2` 完成门槛
- 从“尽量采满”改为“足以推进”

建议完成标准：

- `project_anchor + role_or_responsibility`
- 且命中 `recent_experience` 或 `tech_direction`

#### 5. `StageProgressEngine._snapshot_s3`

文件：
`AI-HR/ai_hr/services/interview_runtime/stage_progress.py`

修改内容：

- 降低 `S3` 离场门槛
- 不再要求强 `jd_hits` 才能离开

建议完成标准：

- 至少 1 个 `core_stack_hit`
- 至少 1 个 `usage_evidence`
- 且有 `middleware_hits` 或 `jd_hits`

#### 6. `StagePolicy` 结构与 helper

文件：
`AI-HR/ai_hr/services/interview_runtime/flow_policy.py`

修改内容：

扩展字段：

- `completion_mode`
- `hard_max_turns`
- `allow_deep_dive`
- `topic_round_limit`
- `must_exit_on_followup_limit`

建议新增 helper：

- `get_stage_hard_turn_limit(stage_code)`
- `get_stage_topic_round_limit(stage_code)`
- `is_stage_deep_dive_allowed(stage_code)`

#### 7. 新增 `runtime_engine.py`

文件：
`AI-HR/ai_hr/services/interview_runtime/runtime_engine.py`

建议新增函数：

- `init_runtime_state(question_pack)`
- `process_candidate_turn(...)`

最小版本职责：

- 调 `evaluate_answer`
- 调 `StageProgressEngine`
- 调 `QuestionFlowEngine`
- 返回 `updated_state + flow_decision`

### 本提交后预期结果

- `S2/S3` 不再天然绕开题目推进状态机
- 编排主逻辑骨架开始集中到 `ai_hr`
- 还不要求 `ten_agent` 已完成接入

### 风险点

- `apply_turn_result()` 的改动会影响 `ai_interviews.py`
- 早期阶段推进变快后，题库顺序不合理的问题会更明显

## 第二个提交：统一题库结构和状态字段，让 `ten_agent` 能消费主逻辑

### 目标

统一 `ai_hr` 与 `ten_agent` 的题库结构、题目语义和状态字段，让两边真正站在同一套 question pack 和 state contract 上。

### 修改文件

- `AI-HR/ai_hr/services/ai_interviews.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/prompt_builder.py`
- `AI-HR/ai_hr/services/llm/prompts.py`

### 需要修改的字段

#### 1. Question Pack 新增标准字段

文件：
`AI-HR/ai_hr/services/ai_interviews.py`

修改函数：
`_normalize_question_item`

新增字段：

- `question_type`

建议值：

- `profile`
- `capability`
- `wrap_up`

推荐映射：

- `S2/S3 -> profile`
- `S4/S5/S6 -> capability`
- `S7/S8 -> wrap_up`

#### 2. 种子题重排

文件：
`AI-HR/ai_hr/services/ai_interviews.py`

修改函数：
`_build_stage_seed_questions`

修改方向：

将当前“自我介绍后直接深挖项目”改为：

- `S2` 自我介绍
- `S3` 最近经历确认
- `S3` 主项目确认
- `S3` 主模块确认
- `S3` 真实使用确认
- `S4` 单主题项目深挖
- `S5` JD 匹配
- `S6` 排障/工程能力
- `S7` 公司反问

文件：
`AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

需要接入和透传的字段：

- `focus_experience`
- `focus_module`
- `active_question_type`
- `active_topic_name`
- `active_topic_rounds`
- `question_completion_reason`

#### 4. `PromptBuildInput` 新增字段

文件：
`AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/prompt_builder.py`

新增字段：

- `question_type`
- `focus_experience`
- `focus_module`
- `active_topic_name`
- `active_topic_rounds`
- `must_transition`
- `candidate_requested_move_on`

#### 5. Stage Prompt 输入语义增强

文件：
`AI-HR/ai_hr/services/llm/prompts.py`

修改函数：
`build_interview_stage_instruction`

新增可用输入：

- 当前 `question_type`
- 当前是否 `must_transition`
- 当前主题已问多少轮

### 本提交后预期结果

- `ai_hr` 和 `ten_agent` 使用相同 question schema
- 自我介绍后的题目顺序开始合理
- prompt 能理解“当前是在补画像还是在问正式能力题”

### 风险点

- 老 question pack 缓存里没有 `question_type`
- prompt 信息变多后，回复可能变长，需要后续继续收紧

## 第三个提交：接入共享 runtime engine，删除 `ten_agent` 本地冗余编排

### 目标

让 `ten_agent` 彻底从“第二套编排逻辑”收敛为“实时执行器”，通过共享 runtime engine 获取下一步动作。

### 修改文件

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/session_context.py`
- 可选新增 `AI-HR/ai_hr/services/interview_runtime/transcript_normalizer.py`

### 需要删除或替换的旧逻辑

#### 1. 删除 `ten_agent` 本地手写 fallback 编排逻辑

文件：
`AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

删除或替换内容：

- 本地手写 3 题 fallback question pack

改成：

- 调 `ai_hr` 统一 seed question builder
- 或加载统一规范化后的 prebuilt question pack

#### 2. 删除 `_handle_interaction()` 中本地阶段推进主判断

文件：
`AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

删除或弱化：

- 基于 `was_satisfied` / `stage_signals_completed` 的本地阶段拍板逻辑
- 针对 `SELF_INTRO -> TECH_STACK`、`TECH_STACK -> PROJECT_DEEP_DIVE` 的硬编码切换

改成：

- 调共享 `runtime_engine.process_candidate_turn(...)`
- 根据 `next_action / must_transition / updated_state` 执行

#### 3. 删除 `S2/S3` 的本地特殊编排

文件：
`AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

删除或迁移：

- 本地 `stage_progress` 驱动转场逻辑
- 本地“如果还缺信号就继续追问”的隐式编排

改成：

- 由共享 runtime engine 返回“继续追问 / 下一题 / 转场”

#### 4. 删除直接基于原始 transcript 构 prompt 的路径

改成：

- 先做 flow decision
- 再做 transcript normalization
- 再做 prompt build

#### 5. 新增 transcript normalization

文件建议：
`AI-HR/ai_hr/services/interview_runtime/transcript_normalizer.py`

用途：

- 对 `AIHR / AIH / AIPR`
- `TTS / TDS`
- `Date / data`
- 其它同音错词

做统一语义归一

#### 6. 增强 `SessionContext`

文件：
`AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/session_context.py`

新增状态：

- `focus_experience`
- `focus_module`
- `known_entities`
- `entity_aliases`
- `active_topic_name`
- `active_topic_rounds`

### 本提交后预期结果

- `ten_agent` 不再维护第二套题目编排
- 实时面试执行完全依赖 `ai_hr` 主逻辑
- ASR 错词不再明显带偏提问

### 风险点

- 如果共享 runtime engine 输出 contract 不稳定，`ten_agent` 会比较脆弱
- transcript normalization 若过度纠偏，可能误解候选人真实意思

---

## 每个提交的验收点

### 第一个提交后

- `S2/S3` 不再无限追问
- 状态机中已经具备统一推进能力

### 第二个提交后

- `ai_hr` 和 `ten_agent` 题库字段一致
- 自我介绍后开始走“画像补全 -> 正式题目”的顺序

### 第三个提交后

- `ten_agent` 不再维护第二套编排逻辑
- 实时行为与后端主逻辑一致
- ASR 错词不会再频繁带偏提问

---

## 推荐提交标题

1. `refactor(runtime): unify interview flow engine for all stages`
2. `refactor(question-pack): standardize shared question schema and stage seeds`
3. `refactor(ten-agent): delegate interview orchestration to shared runtime engine`

---

## 最终效果

改造完成后，面试流程应变为：

- 自我介绍后先补全候选人画像
- 再锁定主项目和主模块
- 再按预生成题目顺序推进
- 每题有限追问
- 候选人答不上来会自然换题
- 系统能够覆盖多个能力面
- `ai_hr` 和 `ten_agent` 共用一套编排主逻辑
