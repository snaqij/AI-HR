# 实时语音面试双轨编排策略 v1 - 提交计划版

## 文档目标

将双轨编排改造拆成可按提交推进的计划，便于控制范围、降低回归风险。

---

## 提交 1：升级 runtime decision contract

**目标**

- 先把“输出模式裁决”引入共享 runtime 层

**涉及文件**

- `AI-HR/ai_hr/services/interview_runtime/runtime_engine.py`
- `AI-HR/ai_hr/services/interview_runtime/question_flow.py`

**核心改动**

- 扩展 `RuntimeTurnDecision`
- 增加：
  - `output_mode`
  - `target_question`
  - `prefetch_question`
  - `should_prefetch_next`
- state 增加：
  - `current_question_asked`
  - `current_question_status`
  - `current_output_mode`
  - `state_version`

**提交后预期**

- ten_agent 还没切换到 scripted 分支
- 但共享运行时已经能输出更强的结构化 decision

**风险控制**

- 不动 TTS/LLM 链路
- 不动公司介绍/收尾逻辑

---

## 提交 2：ten_agent 支持主问题直出

**目标**

- 把 S3-S6 主问题从 LLM 出话链路中剥离出来

**涉及文件**

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

**核心改动**

- `_handle_interaction()` 按 `output_mode` 分支
- 新增 `_emit_scripted_question(...)`
- scripted question 直接 `send_to_tts`

**提交后预期**

- S3-S6 首问不再等待 LLM
- 题库问题第一次真正成为播报主干

**风险控制**

- 先只对 S3-S6 生效
- S1/S2/S7/S8 暂不做激进变更

---

## 提交 3：Prompt 收口为 follow-up only

**目标**

- 让 LLM 只负责追问，不再改写主问题

**涉及文件**

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/prompt_builder.py`
- `AI-HR/ai_hr/services/llm/prompts.py`

**核心改动**

- `PromptBuildInput` 增加 `output_mode`
- prompt 明确：
  - 不复述主问题
  - 不改写题库原题
  - 只允许短追问

**提交后预期**

- follow-up 变短
- scripted question 与 llm followup 边界清晰

**风险控制**

- 只改 follow-up prompt
- 不改 question generation prompt

---

## 提交 4：SessionContext 与 pending question 对齐

**目标**

- 让 scripted question 与 llm followup 都能被 session context 正确记录

**涉及文件**

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/session_context.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

**核心改动**

- 增加：
  - `current_scripted_question_id`
  - `current_scripted_question_text`
  - `last_followup_text`
- scripted question 也要更新 `pending_turn`

**提交后预期**

- prompt 历史不再混乱
- UI question update/final 与真实播报对齐

---

## 提交 5：接入 transcript normalizer

**目标**

- 先解决明显的 ASR 技术词误识别问题

**涉及文件**

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/session_context.py`

**核心改动**

- 新增 `_normalize_candidate_transcript(...)`
- 保存 `raw_transcript / normalized_transcript`

**提交后预期**

- 减少围绕错误术语的追问

**风险控制**

- 初期只做白名单规则归一化
- 不做过强语义改写

---

## 提交 6：加入下一题预取

**目标**

- 当前题追问时异步准备下一题上下文

**涉及文件**

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`
- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/session_context.py`

**提交后预期**

## 推荐合并策略

- 每个提交尽量只改一层
- 先共享 runtime，再 ten_agent，再 prompt，再预取
- 每次提交后都做最小人工验证

---

## 第一阶段建议停点

如果想快速见效，建议做到提交 3 先停一次验证：

- Runtime decision 已升级
- S3-S6 主问题已直出
- LLM 已只负责追问

这一版就已经能显著改善实时体验。
