# 实时语音面试双轨编排策略 v1 - 开发任务拆分版

## 文档目标

本文档用于把“主问题直出 + LLM追问 + 下一题预取”的双轨编排方案，拆成可以直接开工的工程任务。

目标是把当前“题库参与决策、LLM统一出话”的模式，改成：

- 主问题：题库直出
- 追问：LLM生成
- 推进：状态机裁决
- 切题：下一题预取加速
- 容错：ASR归一化兜底

---

## 总体原则

- 题库负责“问什么”
- 状态机负责“什么时候换题、什么时候停”
- LLM负责“怎么追问更自然”
- 预取负责“让切题更快”
- 能结构化的地方就结构化，只有必须灵活的地方才交给 LLM

## Task 2 改哪些函数

### 2.1 `InterviewRuntimeEngine.process_candidate_turn()`

文件：

- `AI-HR/ai_hr/services/interview_runtime/runtime_engine.py`

改造目标：

- 在现有 `next_action / must_transition` 之外，再决定 `output_mode`
- 如果当前题未播过：
  - 返回 `scripted_question`
- 如果当前题已播过且需要继续问：
  - 返回 `llm_followup`
- 如果当前题应结束：
  - 返回下一题为 `target_question`
  - `output_mode=scripted_question`
  - `should_prefetch_next=True`

建议新增辅助函数：

- `_resolve_output_mode(...)`
- `_resolve_target_question(...)`
- `_resolve_prefetch_question(...)`

### 2.2 `InterviewQuestionFlowEngine.apply_turn_result()`

文件：

- `AI-HR/ai_hr/services/interview_runtime/question_flow.py`

改造目标：

- 支持“主问题已播，但未进入追问”
- 支持“追问中但未完成”
- 只有题目完成时才推进 `active_question_index`

建议新增辅助函数：

- `mark_question_asked(...)`
- `mark_followup_started(...)`
- `mark_question_completed(...)`

### 2.3 `InterviewOrchestratorExtension._handle_interaction()`

文件：

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

这是主改造点。

改造成四分支：

- `OPENING / COMPANY_QA / CLOSING` 特殊处理
- `scripted_question`
  - 直接播 `target_question["question"]`
  - 不走 prompt builder
- `llm_followup`
  - 走 prompt build + llm stream
- `transition to next scripted question`
  - 直接播下一题
  - 同时准备下一题预取

建议拆分辅助函数：

- `_emit_scripted_question(...)`
- `_run_llm_followup(...)`
- `_maybe_prefetch_next_question(...)`
- `_apply_runtime_decision(...)`

### 2.4 `InterviewOrchestratorExtension._send_to_tts()`

文件：

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

改造目标：

- 支持 scripted question 的 question metadata 直写
- 保证 `question.update / question.final` 对 scripted 和 llm 两种输出都一致

### 2.5 `InterviewOrchestratorExtension.on_data()`

文件：

- `AI-HR/ten_agent/ten_packages/extension/interview_orchestrator_python/main.py`

改造目标：

- 在进入 finalize 前插入 transcript normalization
- 保留原始 transcript
- runtime 和 prompt 统一用 normalized transcript

建议新增函数：

- `_normalize_candidate_transcript(...)`

### 2.6 `build_interview_stage_instruction()`

文件：

- `AI-HR/ai_hr/services/llm/prompts.py`

改造目标：

- 强化 followup-only 约束
- 明确：
  - 不要复述主问题
  - 不要重写题库原题
  - 只允许一条短追问
  - 如果必须切题，只给一句短收束

建议新增日志点：

- `runtime.output_mode_selected`

- `runtime.prefetch_started`
- `runtime.prefetch_ready`

### 4.6 人工验证清单

建议按以下场景走查：

**场景 1：正常候选人**

- S2 自我介绍
- S3 主问题直出
- 一次追问
- 直接切下一题
- 观察 TTS 延迟是否明显下降

**场景 2：候选人回答很差**

- S3 主问题直出
- 连续两次追问
- 达到上限后强制切题
- 不允许卡死

**场景 3：候选人要求继续**

- 回答“这个我不太清楚，我们继续吧”
- runtime 直接结束当前题
- scripted 播下一题

**场景 4：ASR误识别**

- 故意输入“威力斯”“TDS”“data”
- 验证 LLM 不会围绕错误词乱追问

### 4.7 验收标准

达到下面标准才算完成：

- 主问题播放不再依赖 LLM
- S3-S6 首问延迟明显下降
- 主问题表达稳定，不再漂移
- 追问仍保留自然性
- 达到追问上限后一定切题
- S2 不再进入长时间技术深挖
- 下一题预取能工作，但失败不影响主链路
- transcript normalize 能减少明显误追问

## 第一阶段最小闭环

建议先完成最小闭环：

- `S3-S6 主问题直出`
- `LLM 只做追问`
- `达到上限直接播下一题`

这是第一阶段最关键、最值的版本。

等这个闭环稳定，再继续补：

- transcript normalization
- next-question prefetch
- 更多 observability

---

## 一句话总结

先把实时面试执行链路从“LLM统一出话”改成“题库出主问题，LLM出追问”。

这是当前系统最关键的一次收口。完成后：

- 延迟会明显下降
- 题干会更稳定
- 阶段推进更清晰
- 预生成题库的价值才真正释放出来
